A Mac that runs BB with its Account Pooler serving Claude now says so in its scheduled runs too: the collector asks BB, with `bb pool status --json`, which tools the pool routes and when an enabled account of each last served, and a use in the last 7 days marks the machine `pooled`, with `claude via BB's Account Pooler · accounts not exact` in its note and in the menu bar app's Usage by device. Before, only a run of ai-usage inside a BB thread marked Claude, for 7 days after it. BB's status does not say which of its machines a use was on, so a machine of that BB can be marked for another's sessions. Only the routes and those times are read, not the pool's accounts or their quota.

A subscription whose window fills while the team counts next to no tokens on it is no longer called OUTSIDE when a machine of the team sends that tool's sessions through the pool: the pool serves them from several accounts, and their tokens count for the login of the folder that holds their logs, so the pool may have spent it. ATTENTION says POOLED instead, `+14 points in 1h with next to no team tokens: BB's Account Pooler on mira@mira-mbp may have spent it`, and the report's JSON has `pool_rise` on the account in place of `outside`. Which account the pool spent is still not known, and the tokens of past sessions stay where they were counted.

The install commands and the pictures in `docs/demo` are as in v0.13.2. The README changes only where it says how a machine is marked pooled and what POOLED means.
