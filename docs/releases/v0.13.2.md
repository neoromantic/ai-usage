A Claude account logged in to a folder that shares its session logs with another through a symlink, as each of Orca's Claude profiles shares `~/.claude/projects`, had no reading of its limits, however much it was used: the collector asked neither folder for its usage, since the logs cannot say which login ran a session, and such a folder's own Claude Code does not keep a reading by itself. The default folder's reading went old the same way, while only something else, such as an open `/usage`, refreshed it. Now each such folder is asked whenever those logs show use, so both show their limits again within 15 minutes of the update. A folder whose login is idle gets it renewed on the way, as Claude Code does in any session.

Sessions in such a shared folder now always count for the login of the first folder, the default one when it is one of them. Before, a session that grew while a run read the logs went to whichever folder was read last, so a profile's account could show use it did not have. Sessions BB's Account Pooler serves from several accounts count the same way, so an account the pool serves may fill while the team counts few tokens on it, and ATTENTION may say so.

In the menu bar app, Usage by device says under a machine whose sessions go through BB's Account Pooler that its accounts are not exact, as the Team window's Status already did, and the details of the subscriptions not read say "this Mac" for this Mac in place of its name.

The install commands and the pictures in `docs/demo` are as in v0.13.1. The README changes only where it says how such folders are read and what the app's Usage shows.
