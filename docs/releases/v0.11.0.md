## Quota inside BB comes from your own login

BB's Account Pooler serves the Claude Code and Codex sessions BB starts from one of several accounts, through a hub on the BB server. When ai-usage ran inside such a session, as in a BB thread, it asked Claude Code and Codex for the quota through that hub, and read whichever account the hub picked. Now it drops the hub's route before it asks, so each folder's own login answers. If you point `ANTHROPIC_BASE_URL` at a gateway of your own, that is kept.

## Machines that use the Account Pooler say so

Sessions the pool serves still write their logs to `~/.claude` and `~/.codex`, so their tokens count for the login of that folder, which may not be the account that served them. Neither Claude Code nor Codex records which account answered, so ai-usage cannot fix that. It says so instead. A machine whose Claude Code or Codex sessions went through the pool in the last 7 days shows `claude, codex via BB's Account Pooler · accounts not exact` in its NOTE, and lists those tools in `pooled` in the report's JSON. Per-account numbers are exact only on machines without it.

Codex's logs show when the pool served a session. Claude Code's do not, so ai-usage learns about Claude Code only when it runs inside a session the pool routes, such as `ai-usage` in a BB thread. Scheduled runs then keep the mark for 7 days. Teammates see the mark once every machine in the team runs v0.11.0 or later.

## `ai-usage uninstall`

One command now takes ai-usage off a machine. It asks nothing, so another app can run it. It removes the schedule, the menu bar app with its settings, and the binary the installer put in place. It keeps the state folder, with the team key and the history, so a later install picks up where this one stopped.

- `--forget` also drops this machine from its team on the relay.
- `--purge` does that and removes the state folder too. If no other machine is in the team, save `ai-usage team key` first.

A copy Homebrew installed stays where it is; the command tells you to run `brew uninstall neoromantic/tap/ai-usage`.

## `status --json` before the first run

`ai-usage status --json` used to make a team key and a device id on a machine that had never collected. Now, before the first run, it creates nothing. A new `install` object says which version is installed and where, how it updates, which state folder it uses, whether it has collected, and which binary and state folder the scheduler runs. An installer or another app can ask before anything is set up.

## Upgrade

Script installs update at a scheduled run; Homebrew installs update with `brew upgrade neoromantic/tap/ai-usage` or `ai-usage update`. Relay operators: deploy the relay from this release before collectors update, since snapshots now carry `pooled`.
